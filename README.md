# 投标章节上传助手

这是一个重新实现的、以“先验证，再批量”为原则的本地工具。

它不会修改所选项目里的 Word、PDF 或其他标书成品。转换后的 PDF 只会写入本目录的 `output`，逐文件日志和报告只会写入 `logs`。

## 仓库结构

当前可提交的核心代码只有根目录入口、`bid_upload_assistant/`、`templates/`、`static/` 和 `tests/`：

```text
main.py                       启动本地网页服务
web_app.py                    Flask 页面与接口
bid_upload_assistant/         软件桥接、章节计划、资料识别、上传核验
templates/index.html          网页结构
static/app.css                网页样式
static/app.js                 网页交互
tests/                        离线规则测试与需显式运行的真实软件回归脚本
测试专用/                     本机测试资料，不提交到仓库
output/ logs/ tmp/            本机运行产物，已加入忽略规则
```

旧的 `src/bid_auto_upload` 原型已经不再是运行入口；如果工作区里仍有它的缓存目录，Git 会按 `.gitignore` 忽略，不会进入新仓库。

## 操作顺序

1. 双击 `启动网页版.bat`（或执行 `python main.py`）。浏览器会自动打开本机操作界面。
2. 选择项目文件夹、投标单位和 `.zjzbs`。
3. 点击“连接编制工具并读取章节”。工具只读取软件当前项目的真实章节树。
4. 点击“从成品表自动识别”，程序读取投标人基本情况表，预览公司、法人、地址、联系人和委托代理人；确认后调用软件自身接口写入并读回核验，已有身份证附件不会被替换。
5. 点击成员“从项目标书自动识别”，程序从成品 PDF 合并姓名、岗位、身份证及证书资料；页面逐项预览后再确认写入，写完会从软件重新读取核验。
6. 先导入一次工程量清单并由软件重新读取核验；报价封面、工程量清单报价和已标价清单均交给软件生成，不再匹配普通 PDF。
7. 投标函在编制工具内人工填写后，回到网页点击重新读取核验；法定代表人身份证明日期可直接在网页选择并写入核验。
8. 网页按软件章节逐项区分：上传文件、人工填写、选择日期、软件自动生成、“若有但没有文件”自动跳过。无需附件的章节可单独点击“执行下一章”试跑。
9. 只选择一条运行“验证上传 + 下一章”。成功必须同时满足：附件链接读回、程序在真实界面点击“下一章”、小章节读回 `isSubmit=1`、界面灰色勾变为绿色勾。
10. 单文件完整验证成功，且清单、人工填写、日期等前置项均完成后，批量逐章处理才会解锁。没有对应成品的章节会明确记录为跳过，仍在真实界面逐项点“下一章”。

## 编制工具连接

软件的页面使用 CEF，真实接口通过 `window.jsBridge` 暴露。文件上传和回读使用软件自身桥接接口；小章节完成则由程序选中真实章节并点击可见的“下一章”。这两部分都要重新读取软件状态才算成功。

启动编制工具时需要带调试端口，例如：

```powershell
& 'C:\Program Files\投标文件编制工具\tenderBidApp.exe' --remote-debugging-port=9222 --remote-allow-origins=http://127.0.0.1:9222
```

若软件因管理员权限无法从普通终端启动，请以管理员身份运行这条命令。工具会明确提示连接失败；连接失败时绝不会开始上传。

## 安装

```powershell
python -m pip install -r requirements.txt
python main.py
```

运行回归测试：

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
```

`tests/live_*.py` 会真实写入编制工具测试项目，只有明确要做现场回归时才手动运行，不属于默认测试套件。
